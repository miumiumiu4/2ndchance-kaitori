# 記事の書き方（ブログの予約配達）

記事は `content/posts/` に1本1ファイルで置く。日付を入れて積んでおくと、**その日の朝 7時（日本時間）ごろ**に自動で公開される（`.github/workflows/publish-daily.yml`）。

## 1. ひな形を作る
```sh
node tools/new-post.mjs "片付けを始める順番" --date 2026-11-10 --tags 片付け,遺品整理 --slug katazuke-junban
```
→ `content/posts/2026-11-10-katazuke-junban.md` ができる（`status: draft`）。`--slug` は URL になる部分（英小文字・数字・ハイフン）。省くと `kiji` などになるので、付けるのがおすすめ。

## 2. 先頭（frontmatter）
```yaml
---
title: 片付けを始める順番          # 記事の題名（見出し・一覧・検索結果に出る）
date: 2026-11-10                   # 公開する日。ファイル名の日付と同じにする
summary: 片付けをどこから始めるか、順番の目安をまとめます。   # 一覧・RSS・検索結果に出る1〜2文
tags: [片付け, 遺品整理]            # 分類（いくつでも）
cover: assets/blog/katazuke-junban-01.webp   # 任意。記事の上に出す写真
status: scheduled                  # draft（下書き・出さない）か scheduled（予約・日付が来たら出す）
---
```
- **公開されるのは `status: scheduled` で、`date` が今日（日本時間）以前の記事だけ**。未来の日付は、その日の朝まで公開用の写しにも入らない。`draft` はいつまでも出ない。
- 日付を変えたら**ファイル名の日付も変える**（違うと組み立てが止まる）。
- 公開済みの記事を引っ込めたいときは `status: draft` にして push する（次の公開で消える）。

## 3. 本文（Markdown）
| 書き方 | 出方 |
|---|---|
| `## 見出し`／`### 小見出し` | 見出し（`#` 1つも大見出し扱い。題名は frontmatter の title） |
| 空行で区切る | 段落。段落の中の改行はそのまま改行 |
| `- 項目` | 箇条書き |
| `1. 項目` | 番号付き |
| `**太字**` | 太字 |
| `[料金・実績](price/)` | リンク。サイト内は**サイトの直下から**書く（`kaitori/`・`kataduke/`・`seiri/`・`flow/#faq`）。外は `https://…` |
| `![写真の説明](assets/blog/katazuke-junban-01.webp)` | 写真 |
| `> 文` | 引用 |
| `---` | 区切り線 |

HTML のタグは使えない（書いても文字のまま出る）。

## 4. 写真の置き方
- `assets/blog/<slug>-<番号>.webp`（例 `katazuke-junban-01.webp`）。横 1200px 程度、300KB 以下が目安。
- 予約した記事の写真が置かれていないと組み立てが止まる（写真を先に push する）。
- 写真は `assets/blog/` に置いた時点で公開される（記事より先に見えてもよい写真だけ置く）。
- 人の顔・名前・表札・住所・車のナンバー・郵便物が写ったものは使わない。詳しくは `assets/blog/README.md`。

## 5. 確かめて出す
```sh
node tools/build.mjs --today=2026-11-10   # その日に何が出るかを手元で見る（blog/ に作られる。blog/ はコミットされない）
node tools/build.mjs && npm test          # 最後は今日の日付で組み立てて、テストが全部緑
git add -A && git commit -m "記事：片付けを始める順番（11/10 公開）" && git push origin main
```
push したあとは、日付が来た朝に自動で公開される。すぐ出したい（今日の日付の）記事は、push した時点で公開される。

## やってはいけないこと
- **他社のサイトや書籍・雑誌の文章を写さない**（言い回しを少し変えただけのものも不可）。自分の言葉で書く。引用するときは `>` で短く、出典を書く。
- **個人情報を書かない**：お客様の名前・住所・町名より細かい場所・電話番号・家の様子が分かる写真。事例は「合志市内・2LDK」のように、本人が特定できない書き方にする。
- **商標名（メーカー名・商品名・他社のサービス名）を見出しやタイトルに使わない**。本文で触れるのは必要な範囲だけ。
- **金額は `data/prices.json` と矛盾させない**。金額を書くときは「目安」と書き、「最終額は訪問査定で確定」を添える。料金表が仮（`provisional: true`）のあいだは具体的な金額を書かず、[料金・実績](price/) へのリンクにする。
- 「必ず」「絶対」「日本一」など、言い切りや根拠のない比較は書かない。
